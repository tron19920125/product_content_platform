# ADR-001：新建平台目录，保留原 MVP 作为能力基线

## 状态

已采用。

## 决策

新平台在 `product_content_platform/` 下独立建设，不在 `image_qa_mvp/` 内继续扩展。

## 原因

原 MVP 的目标是验证图片生成、自动审查、候选排序和一轮修复。新平台新增商品档案、页面规划、固定模板、图文分层、多 SKU、配方管理、本地持久化和新的业务页面，两者的产品结构和运行方式已经不同。

原 MVP 中 Web 页面、HTTP 处理、上传、任务状态和流程编排耦合较重。原地扩展会使新领域逻辑依赖演示结构，并增加回归风险。

## 复用方式

新平台先定义自身需要的模块接口，再通过适配层接入以下既有实现：

- 图片生成与编辑；
- Azure Vision OCR；
- Agent 审查计划；
- 多模态图片审查；
- 目标区域和非目标区域变化证据；
- 候选评分、排序和一轮修复。

旧模块只作为适配器背后的实现，不向新页面暴露原 MVP 的数据结构和调用约束。经过验证后，可将稳定实现迁入新项目并保留回归测试。

## 影响

- 原 MVP 可继续独立运行和演示。
- 新项目可以重新设计数据模型、接口和页面。
- 不迁移原 MVP 的临时任务状态及历史文件路径。
- 历史结果继续作为测试样本和生成案例使用。
