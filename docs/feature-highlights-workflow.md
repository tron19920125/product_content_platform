# 图文卖点组工作流

“图文卖点组（Feature Highlights）”用于电商详情页中的功能点、利益点或能力点表达。新模板默认采用“完整卖点模块随主图生成”：图形、短标题和说明由同一次图片生成自然融入场景，避免后贴图标和后排文字因模型构图偏差而错位。主标题与正文继续使用可审计、可重排的后期文字层。

## 三种生成方式

- `scene_baked`（推荐）：完整卖点模块随主图生成。内容规划仍由 AI 预填并允许用户修改；确认生产后，图形、卖点标题和卖点说明成为底图的一部分，不能在文字工作台中单独改字。
- `scene_integrated`（兼容）：主图只生成无字卖点视觉，平台在后期叠加可编辑卖点文字。保留给已有项目，不再作为新模板默认值。
- `independent_icon`（兼容）：平台单独生成透明图标，再与卖点文字进行后期合成。仅用于回放旧资产或明确需要独立图标层的页面。

## 完整链路

1. 版式模板通过 `feature_slots` 声明卖点组预留区、行列、最大项数、图文关系、图形占比、标题/说明字号提示和 `visual_mode`。组框可在版式中心直接拖拽、缩放；它是图片模型必须遵守的生成边界。
2. 内容规划通过 `PageItem.feature_points` 保存结构化卖点。每项包含标题、说明、视觉语义和 `fact_refs`。AI 可先预填，用户可修改或重新规划，确认前不会调用图片模型。
3. `scene_baked` 将组框拆分成每个卖点单元格，把相对坐标、视觉语义、准确标题、准确说明、图文关系和字号参考一起写入主图 Prompt。Prompt 只允许卖点预留区出现这些指定文字，主标题与正文区域仍严格禁止图片模型生成文字。
4. 图片模型基于全部商品参考素材，在一次生成中完成商品、角度、场景、材质、光影和完整卖点模块。卖点模块必须采用同一视觉体系，并与环境的材质、透视、光向和阴影一致，不得表现为后贴 PNG、悬浮 UI 或突兀白卡。
5. 确定性合成器只绘制主标题、正文和用户新增的普通文本框。`scene_baked` 卖点组仍保存在 `TextDocument` 和组合元数据中作为只读审计证据，但不会再次创建图标层或卖点文字层，因此不会发生重复叠加和二次错位。
6. 质检使用 OCR 核对主标题、正文和生成在卖点区域内的精确卖点文案；标题/正文由文字层负责，卖点文案由主图负责。卖点区域中的规划文案不再被误判为底图脏字，缺字、乱码、额外文字或明显错位会建议重新生成，而不是无效的文字重排。
7. 页面图层工作台把 `scene_baked` 卖点组显示为只读，清楚提示“回内容规划修改后重新生成本页”。主标题、正文和普通文本框仍可继续使用字体、字号、颜色、描边、位置和 AI 初排。
8. 针对单张候选的自然语言调整会携带同一份卖点模块约束，保留或重新生成完整卖点模块；原候选仍保留，便于审计和回滚。

## 质检与交付证据

- 文案检查覆盖标题、正文和每个卖点项；`fact_refs` 缺失会进入问题列表。
- 布局检查保存卖点组与各单元格坐标、商品主体重叠率、`feature_visual_mode`、`feature_copy_generated_with_base` 和合成溯源。
- `scene_baked` 导出包含最终图、底图、透明主文字层、QA 文件和 `project_summary.json`，不创建多余的透明卖点图标层。长图拼接继续使用最终合成图。
- 图片模型绘制精确中文存在概率性；平台通过 OCR 和候选重生成进行约束，但不会用后期叠字伪装成“纯生成”。这是自然融合与生成后可编辑性之间的明确取舍。

## 内置验收示例

部署后可直接打开 `[示例] 4K 横版 · 三项图文卖点`。规划页使用 3840×2160 横版模板演示画布优先工作台、三项完整卖点模块预留区和右侧商品区域。修改卖点后确认规划并重新生成一页，即可验收 `scene_baked` 链路；仓库中已有的旧候选仍按其历史模式保留，不会被静默改写。
