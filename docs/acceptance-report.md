# MVP 验收报告

## 卖点视觉显著性收口（2026-08-26）

- 当前产品路径仅保留 `scene_baked` 与 `scene_integrated` 两种主图原生卖点视觉；历史 `independent_icon` 读取时单向迁移为 `scene_baked`，API、前端、导出均不再提供独立透明图标的生成、替换、下载或分层交付。
- 主图 Prompt 现在携带每个卖点单元格及图形子区域的百分比坐标，要求图形填满子区域的 75%—90%，使用实色/半实色、清晰轮廓和强对比，并明确禁止白色半透明玻璃、微弱浮雕、纤细线稿和低透明度光效。
- QA 新增逐卖点图形区域的显著性证据：亮度标准差、P10—P90 对比跨度、P05—P95 动态范围和显著像素比例。接近不可见为 P1 并要求重生，偏弱为 P2；多模态审查同步以 25% 缩略图辨识度复核。
- 模板安全区、卖点框、商品框和文字框坐标均未改动。
- 真实 3840×2160 / High 单页候选 `c99cd07c-bd5b-4fe8-bdd3-ceb00f7f7e85` 已完成：三枚深森林绿/金色卖点徽章在缩略图中清晰可辨，三个图形区的显著性均为 `pass`，标准差为 65.39 / 72.68 / 73.88，P10—P90 对比跨度为 159 / 175 / 175，显著像素比例为 24.33% / 25.22% / 25.85%。候选仍因第三项生成文字未逐字命中及商品面板/品牌标识一致性进入人工复核；这些问题被 QA 正确保留，没有被显著性通过掩盖。

## 卖点整组随主图生成增量验收（2026-08-20）

- 产品语义：内容规划继续由 AI 预填卖点标题、卖点说明与图形语义，用户可编辑确认；默认 `scene_baked` 模式把每项“场景化图形 + 标题 + 说明”作为一个完整视觉模块随主图生成。页面主标题与正文仍使用可编辑的确定性文字层，避免把所有文案固化到底图。
- 模板约束：版式模板保存卖点组的归一化位置、大小、行列、图形占比及标题/说明字号提示。主图 Prompt 会展开每个卖点单元的相对坐标、准确文案与图形语义，要求模块与场景材质、光影和透视自然融合；横版内置模板的卖点区调整为画布左下 `4%–43% × 50%–88%`。
- 生产与编辑边界：`scene_baked` 不再生成或贴入独立图标层，也不创建卖点文字叠加层；候选审计信息记录 `render_owner=base_image_model`。卖点文案修改后需要重新生成该页面，避免出现错位和拼贴感；历史 `scene_integrated` 与 `independent_icon` 仍作为兼容路径保留。
- 质检：最终图 OCR 同时检查主标题、正文和卖点组；底图保留区检查只限制主标题/正文区域，卖点区只允许规划中的准确卖点文案。修复了商品品牌 OCR 插入跨行正文导致的误报，并为随主图生成的卖点提供专门的 LLM 审查规则与重新生成建议。
- 真实 Azure 单页：`[示例] 4K 横版 · 三项图文卖点` 使用 `3840×2160 / High` 生成完整洗护场景与三组场景融合卖点。最终候选 `ce5a1e35-8e4f-4ec0-b0a3-fbfa7dc5a0de` 的 OCR/LLM QA 为 `pass / 97`、0 个问题，三组标题与说明逐字命中，商品一致性、布局和视觉质量均通过，并已按正常 QA 流程人工批准。
- 自动化：后端、前端 TypeScript 与 Vite 生产构建均通过；浏览器验收确认项目完成、当前候选通过且交付导出可用，控制台无应用错误。
