# 可编辑文字图层工作流

本文定义“模板预留区、页面文案、候选文字文档”的职责，避免把营销文字再次交给图片模型生成。

## 三层数据关系

1. **模板文字预留框（`text_slots`）**：只约束哪里适合放字、文字角色、最大行数和默认风格。模板编辑器支持任意新增、删除、拖拽和缩放预留框；旧模板会自动迁移为标题和正文两个预留框。
2. **页面规划文案**：保存经过用户确认的标题、正文和商品事实，是默认文案来源，不决定最终像素位置。
3. **候选文字文档（`TextDocument`）**：属于某一张候选图，包含最终可编辑的任意文字图层。每个图层具有内容、比例坐标、字体、字号、颜色、粗细、行高、字距、对齐、旋转、透明度、描边、阴影、背景、锁定与层级。

图片模型只生成商品和场景底图，并按模板预留区域留出低细节空间。确定性服务端渲染器再把文字文档输出成透明 `text_layer.png`，与没有营销文字的 `base.png` 合成为 `composed.png`。调整排版不会再次调用图片模型。

## 用户流程

1. 在候选图上打开“文字重排”。第一次打开会把模板预留框和页面文案转换为文字文档 v1。
2. 点击“AI 帮我初排”可根据画布比例、文字角色和设计要求生成新版本；AI 不修改底图，也不会新增商品事实。
3. 用户像 PPT 一样新增、删除、拖拽、缩放文本框，并调整字体、字号和样式。保存采用乐观版本校验，过期页面不能覆盖新版本。
4. 点击“应用排版”生成一个新候选。来源底图字节保持不变，新候选初始为“尚未质检”。
5. 用户可以手动执行 QA，或明确选择“跳过自动质检”。跳过时必须填写人工说明，审计状态为 `skipped_by_human`，不会伪装成 QA 通过。

## 字体治理

字体目录只展示明确允许商用并记录许可证来源的字体。浏览器预览和服务端渲染使用同一官方字体文件；字体首次使用时下载到受控缓存目录。当前目录包含 Noto/思源、霞鹜文楷、得意黑、站酷系列和多款书法/手写字体。部署环境可以设置 `PCP_FONT_DOWNLOAD=0` 禁止运行时下载，此时渲染器使用跨平台系统回退字体。

## 主要接口

- `GET /api/fonts`
- `GET /api/fonts/{font_id}/content`
- `GET /api/candidates/{candidate_id}/text-document`
- `PUT /api/candidates/{candidate_id}/text-document`
- `POST /api/candidates/{candidate_id}/text-document/ai-layout`
- `POST /api/candidates/{candidate_id}/text-document/apply`
- `POST /api/candidates/{candidate_id}/qa`
- `POST /api/candidates/{candidate_id}/review`（支持 `skip_qa`）

模板中的文字预留框通过版式草稿创建/更新接口中的 `text_slots` 字段保存。
