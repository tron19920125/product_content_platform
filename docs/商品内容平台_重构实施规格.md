# 商品内容平台重构实施规格

日期：2026-09-03
状态：Q49 已于 2026-09-03 整体确认，作为本次重构实施基线。
实施分支：codex/product-studio-refactor；从 addedd4 新建。不在 main 开发，也不合并回 main。实施进度见[实施记录](重构实施记录.md)；本规格不代表功能已经完成。

阅读顺序：先看第 1–3 节确认产品和页面，再看第 4–8 节确认操作边界。第 9–10 节用于开发与验收。
本稿中的既定规则来自[决策记录](research/2026-09-03-重构决策记录.md)。具体布局、默认组合、输入上限、评分权重和删除细则由代理补全，并随 Q49 整体确认；模型尺寸支持和评分效果仍须实测。旧规格与本稿冲突时，以本稿为准。

## 1. 本次重构交付什么

做成电商运营能独立使用的本地创作平台，不先建项目、不先配置模板。五个工具共用商品输入、生成任务、结果、编辑、素材与历史。

| 首期保留 | 首期不做 |
|---|---|
| 电商套图、A+ 详情图、营销主图、场景图、卖点图 | 多 SKU 批量创作和文件夹/图片包、CSV/XLSX 批量导入 |
| 图文一起生成、无营销文字底图、独立文字/图片图层编辑 | 3D、模特库、完整企业品牌管理、通用专业设计软件 |
| 自然语言 AI 修改、逐图评分、低于门槛一次自动修复 | 人工编辑质检、审批/驳回/豁免、质量下载门禁、额度系统 |
| 单图/套图版本、参考对比、局部重生、下载和长图 | 自动图文分层、圈选蒙版重绘、完整抠图/扩图工具 |
| 轻量素材、独立作品收藏、同商品继续创作、换商品复用 | PDF/Word 规范书解析、HEIC 转换、PSD/通用工程导出 |
| 本地单人、固定技术配置、国内中文与亚马逊英文预设 | 多用户权限、云端 SaaS、自动发布店铺、公开素材社区 |

不要求旧界面、旧数据或旧项目兼容。原始商品资料、历史验收样本和文档不属于可随意清理的运行数据。A+ 指模块化内容规划和图片制作，不承诺直接发布亚马逊或保证通过其平台审核。

## 2. 页面组织与视觉

### 2.1 导航与页面

| 页面 | 布局与主要内容 | 关键操作 |
|---|---|---|
| 创作工作台 | 左侧五工具导航，中间输入面板，右侧结果；默认电商套图。创作记录为可收起的抽屉，不常驻第三个窄栏 | 上传/选素材、填写要求、选尺寸和数量、生成；查看当前任务 |
| A+ 模块规划 | 同一工作台内切换“模块方案 / 生成结果”；模块以卡片展示，直接改文案、画面描述和顺序 | 增删/排序模块、重新规划、生成图片；不逐字段采用建议 |
| 图片详情 | 工作台内的大图覆盖层，保留返回位置；大图区、候选/版本缩略条、信息侧栏 | 参考对比、切版本、再生成、AI 修改、手动编辑、下载、加入素材库 |
| 手动编辑器 | 站内全屏，左侧工具/图层，中间画布，右侧所选对象属性，顶部保存状态与完成按钮 | 编辑独立文字、加图/Logo、调图层、撤销重做、完成编辑 |
| 素材库 | 图片卡片为主；商品图、风格参考、Logo、创作作品分类；搜索及筛选在顶部 | 上传、预览、改名、选入创作、继续编辑、复用、删除 |
| 创作记录 | 全局任务卡片，按最近更新时间排序；按工具、状态、关键词筛选；可切换结果图视图 | 恢复草稿/任务、看历史版本、再创作、下载、收藏、删除 |

“项目库”由创作记录承接，不另设强制项目层。工具切换不丢草稿；默认恢复该工具最近一次未完成输入。只有主动“继续创作/复用”才携带其他任务的商品资料，不静默串商品。

### 2.2 页面尺寸与视觉默认值

- 桌面 Chrome/Edge 为主，优先验收 1280、1440 宽度。默认浅灰背景、白卡片、紫蓝主色；使用自己的名称与资产。
- 建议导航宽 168、输入栏宽 320、页头高 64；结果区自适应，内容间距 16/24，常用按钮高 40。记录抽屉宽约 320，展开不挤压成图。
- 详情默认突出当前结果；点击“参考对比”后并排显示所选原始商品图与当前 AI 底图，支持切参考、缩放和适应画布。不是用商品参考代替版本前后对比，两者入口分开。
- 小于 1280 时收起导航文字、把输入/记录折叠为抽屉；不能把关闭、保存、生成等按钮裁到窗口外。不承诺手机完整编辑。
- 普通正文 14–16，页面标题 22；主色建议 #635BFF，背景 #F7F8FC，正文 #182230。状态同时用文字说明，不只靠颜色。
- 同一区域只突出一个主要动作。评分、历史、更多设置收敛在辅助位置；不展示模型名称、Prompt、配方或技术问题码作为业务操作前置。

### 2.3 结果与空白状态

首次进入显示上传引导和少量自有案例，不虚构生成历史。案例仅回填，可修改后再生成；默认不把客户原始资料打包成公开案例。

生成后每张候选完成即展示；未完成项用占位卡片显示阶段。点击图片打开详情，勾选框用于多选，不让“看大图”和“选图片”争用一次点击。失败卡片有“重试此项”，页面顶部有“补生成失败项”；没有确认的模型结果不计入失败重试集合。

## 3. 五个工具的输入与默认值

### 3.1 公共输入

| 字段 | 控件、默认与校验 |
|---|---|
| 商品图片 | 唯一无条件必填项；PNG/JPG/WebP，拖拽、多选、粘贴或从素材库选择。标明主参考，可排序和移除；普通多图默认同一商品 |
| 商品名称、SKU、品类 | 可选，默认空；识别建议可修改，不预填演示型号、容量等事实 |
| 卖点/制作要求 | 多行输入，默认空；允许粘贴文字。可展开标题、正文、参数等可选字段，不要求使用结构化表格才能生成 |
| 商品事实 | 可选键值/说明及来源；数值、型号、认证、尺寸、功效和比较信息必须有依据。风格参考中的文字不作为商品事实 |
| 市场与语言 | 国内中文、亚马逊英文两组预设；套图及三个单图默认国内中文，A+ 默认亚马逊英文；可切换，不把翻译当成新增事实 |
| 风格 | 默认自动匹配；建议提供简约、居家、科技、高端、促销等少量可改偏好。另设风格/构图参考，不与商品图混为一个上传区 |
| 品牌偏好 | 可选品牌色、常用字体及 Logo；不要求建立品牌档案。生成字体只追求风格近似，手动文字层才使用实际字体文件 |
| 文字模式 | 图文一起生成 / 只生成底图；套图、A+、营销主图和卖点图默认图文一起生成，场景图默认只生成底图。无字指不加营销文字，保留商品实际 Logo、标签和面板标识 |
| 尺寸 | 生成前选择比例及分辨率，显示实际宽×高；默认高清约 2K，质量固定 High；不选模板、不开放任意像素输入 |
| 候选数 | 1/2/4，默认 1；单图表示候选张数，套图/A+ 表示每页/模块的候选数。按钮旁显示页数×候选数=初始总图数，不显示额度或余额 |

建议初始应用上限为单文件 25 MiB、商品参考最多 6 张、风格参考最多 2 张；还需受实际部署的总参考图上限约束，AI 修改需预留来源底图的位置。前后端使用同一能力配置，超限在提交前提示。不得“上传了 8 张，实际静默只用 3 张”。这些数量是应用设计建议，不声称是 Azure 的统一上限。

创作页上传的文件用于当前草稿/记录；进入公共素材库由用户选择，素材库内上传则直接入库。保留源图，纠正预览方向，识别不支持/损坏文件，不能仅按扩展名判断有效图片。

用户指定的文案优先按原文生成；可选字段为空时允许组织一般描述，但不编造规格、功效或认证。只有图也能开始一般视觉创作；尺寸、规格对比等页面出现条件性缺项时，明确要求补充、删页或跳过，不因“只有图片必填”而放任虚构。

### 3.2 工具差异

| 工具 | 特有输入与默认 | 主操作 |
|---|---|---|
| 电商套图 | 选图片用途；默认建议营销、场景、卖点三页，均可移除/重复添加。相同商品共享风格，允许单页例外 | 生成套图；直接出组图，不强制逐页规划确认 |
| A+ 详情图 | 选模块及核心说明；默认首屏、核心卖点、场景三个模块，均可调整 | 先“生成模块方案”，可改文案与排序，再“生成详情图” |
| 营销主图 | 可选营销目标、主副标题、活动信息；金额/折扣/日期不自动编造。默认图文一起生成、方图 | 生成图片 |
| 场景图 | 场景描述/参考、构图与氛围；默认无营销文字、竖版 3:4。描述为空时可基于商品提出合理场景，不生成未确认功能说明 | 生成场景图 |
| 卖点图 | 核心卖点、可选主副标题、图标/信息呈现偏好；默认图文一起生成、方图。无事实性卖点时不硬造功效 | 生成卖点图 |

套图用途：白底、营销、场景、卖点、细节、尺寸、功能说明、使用步骤、对比、包装清单，共 10 类；最多 15 页，候选另计。

A+ 模块：首屏、品牌介绍、核心卖点、多特性、场景、细节、规格对比、使用说明，共 8 类；最多 6 个模块，候选另计。默认横版 16:9，可在生成前修改。品牌介绍缺事实时不能编造品牌沿革；比较内容缺数据时提示补充或去掉相关模块。

套图/A+ 可重复添加类型和自定义说明。默认组合不包含必须有具体数值的尺寸、对比等页面。重新规划产生可返回的方案版本，提示其会替换当前模块方案，不静默覆盖用户已改文案。

### 3.3 尺寸映射建议与能力验证

以下是 UI 拟提供的预设，不是本轮已经完成真实模型测试的支持清单。比例精确，像素按模型适配要求选择；“约 1K/2K”是应用分组名，不把所有尺寸都写成 1024/2048 正方形。

| 比例 | 标准（约 1K） | 高清（约 2K，默认档） |
|---|---|---|
| 1:1 | 1024×1024 | 2048×2048 |
| 3:4 | 864×1152 | 1536×2048 |
| 4:3 | 1152×864 | 2048×1536 |
| 2:3 | 768×1152 | 1344×2016 |
| 3:2 | 1152×768 | 2016×1344 |
| 16:9 | 1280×720 | 2048×1152 |
| 9:16 | 720×1280 | 1152×2048 |

生成前可改整组默认尺寸，也可明确覆盖单页/模块；不要求编辑模板。单页再生成沿用该页设置；AI 修改默认保持来源底图尺寸，改比例通过新生成处理，避免人工图层被静默拉伸。

现有能力接口把模型名写死，尺寸校验也只是本地规则；部署实际支持必须按配置和验证结果维护。上述尺寸均可按旧本地约束进行校验，但不能据此宣称全部原生可生成。发布时只启用已核实的部署档位；不支持时明确提示，不静默裁剪、拉伸、降尺寸或更换模型。4K 实验档不进入首期普通界面。

真实尺寸与模型效果的验证是交付条件；未完成时必须列为待验收，不能用本地模式替代。[现有尺寸声明](../backend/src/product_content_platform/domain/image_configuration.py:9)、[实际请求参数](../backend/src/product_content_platform/integrations/azure_image_client.py:149)。

## 4. 结果、版本与编辑

### 4.1 三种主要操作必须分清

| 操作 | 使用什么输入 | 产生什么 |
|---|---|---|
| 重新生成 | 当前页的商品参考、事实及已保存生成设置 | 新候选/批次，旧图保留；不把旧手工图层默认贴到完全重新生成的构图上 |
| AI 修改 | 明确选中的 AI 底图、原商品参考及本次修改要求 | 新 AI 底图及关联版本；保留来源选中版本的人工图层，必要时用户再调整位置 |
| 手动编辑 | 所选版本的底图及独立文字/图片层 | 自动保存草稿；完成编辑生成并选用新版本，不调用 AI、不质检 |

每个页面有一个当前选用版本，用于组图预览、整组下载及收藏。选用不是审核；任一已有图片可单独下载。图片详情提供来源图与修复/修改前后的版本对比，不能用旧报告冒充新版本的报告。

候选、修复版和手动版有明确来源关系，不覆盖旧图。原生图片文字是像素：改字属于 AI 修改，可能改变周围画面；不能给它套一个假文本框。人工新增文字不会自动消除底图已有文字。

### 4.2 手动编辑器

- 独立文字支持画布内双击编辑；字体、字号、颜色、粗斜体、对齐、行距、字距、描边、阴影按整个文本框设置。
- 支持选择、移动、缩放、旋转、复制和删除对象；调整文本框宽高用于换行，字号由字号控件调节，不让同一手柄的行为含糊。
- 支持加图/Logo，保持图片长宽比；图层可排序、锁定、隐藏。锁定同时限制画布手势及属性修改，解锁后再编辑。
- 支持撤销/重做；编辑中的输入框优先使用文本编辑快捷键，不能误删整层。建议 Cmd/Ctrl+Z 撤销、Shift+Cmd/Ctrl+Z 重做、Delete 删除选中对象、Esc 退出选中；均提供可见按钮。
- 顶部显示保存中/已保存/保存失败。自动保存只更新草稿，完成编辑才生成新版本并选用；直接返回不替换当前成图，再进可继续或丢弃草稿。
- 只提供已加载的字体，保留字体来源与授权登记，不承诺自动完成法律授权判断；首期不增加用户字体上传。预览与最终合成使用同一文本布局数据，避免导出另行缩字导致不一致。
- 不做复杂富文本、矢量绘制、动画或另一套专业设计页。

手工版本标“已手动编辑”，不显示一个新总分。AI 源底图的分数可在对应详情中查看，必须标“AI 底图评分”。后续 AI 修改只检查新 AI 底图，不把人工文字、Logo 或未应用草稿送去审查。

## 5. AI 评分与一次自动修复

评分是帮助选图的结果，不是审批流程。只检查 AI 生成/AI 修改的内容。

| 检查范围 | 判断依据 |
|---|---|
| 商品外观 | 原始商品参考；结构、颜色、部件、Logo 等是否存在可确认差异 |
| 文案与事实 | 用户确认资料及生成要求；检查漏字错字、未确认参数或无依据声明 |
| 可读性与版式 | AI 图中文字清晰度、主体遮挡、边缘裁切、实际输出尺寸 |
| 品牌与整套风格 | 已提供的颜色/风格要求，以及当前选用 AI 底图的组合；没有依据的项目不冒充已验证 |

建议初始分项权重为商品外观 35%、文案事实 30%、可读性/版式 25%、品牌/整套风格 10%；仅对适用且完成的项目归一加权。无营销文字时不强行扣标题分，但商品标签仍可检查。权重须通过固定样本校准，不沿用“有参考图就给高分”等固定值。

确定的关键错商品、错型号或虚构关键参数应在评分规则中显著降分，不能被背景美观抵消；建议明确证据支持的关键错误将总分上限设为 59。缺资料本身不伪装成视觉错误，更不能通过重绘编造缺失资料。

报告明确区分“有证据的错误”“待确认的视觉疑点”和“风格建议”。疑点须说明不确定性，不按确定错误直接触发关键错误分数上限；主观审美建议不能单独判废。该区分只帮助理解分数，不引入人工审批或豁免流程。

执行规则：

1. 原图产出后先展示“检查中”，报告统一 0–100 分；低于 60 分触发修复，60 分及以上不自动干预。
2. 每次用户主动 AI 生成/AI 修改的每张结果最多追加一次修复。修复图再检查，但不递归修复；新的主动生成/修改才是新一轮。
3. 原版与修复版均保留。两者有可比评分时默认选高分；同分保留原选图。修复失败或没有有效分数时保留原图，提示状态，不能把失败当作分数为 0。
4. 自动选高分仅在用户未主动换图或完成手工编辑时生效；用户已作选择则提示有新版本，不抢回当前选图。
5. 安全的质检服务异常最多自动重试两次。必要检查仍未完成时显示“检查未完成”，不伪造总分，不因此触发质量修复；可手动重检 AI 底图。
6. 事实缺失/冲突应先补充依据，不允许用自动修复造事实。已成图仍可下载，不恢复审批/原因必填。
7. 整套只检查当前选用 AI 底图组合，不穷举所有候选排列。整套报告绑定组合；AI 生成/修改流程中更新，纯人工编辑/排序不触发模型检查，变更组合后的旧报告不能冒充新组合报告。检查发现关联低分时也不能重置该结果已用过的一次修复。
8. 手动保存、完成编辑、收藏及下载均不触发质检。只展示分数、简明问题和必要证据，不做独立质量工作台。

首期不承诺一次修复必然变好，不能以“自动质检”替代真实样本验证。评分未知与低分是两种状态。

## 6. 任务、局部失败与恢复

| 情况 | 前台行为 | 必须保持的后台边界 |
|---|---|---|
| 提交生成 | 按钮防连点，立即出现任务及初始总图数 | 一次提交有稳定标识；不能因双击/重发创建重复请求 |
| 多页/多候选 | 每张完成即显示，成功项可查看与下载 | 按候选持久化，不等整页候选全部成功才入库 |
| 部分失败 | 明确失败页/候选，提供局部重试 | 不重跑已成功项，不覆盖其手工编辑 |
| 页面排序/增删 | 排序立即更新展示与导出；增页先形成待生成项 | 页 ID 稳定，不能用序号关联旧结果；生成中的在途结果仍保留在历史 |
| 修改输入或风格 | 草稿保存，旧图提示“设置已修改” | 已发请求绑定提交快照；用户显式选重生范围 |
| 关闭/刷新浏览器 | 返回后恢复输入、结果及进度 | 服务继续运行；刷新只读任务，不重发模型调用 |
| 停止后续生成 | 保留已有结果，说明已发请求可能继续返回 | 停止派发后续生成/修复；不虚称已撤销上游调用 |
| 服务重启 | 展示中断及可恢复进度 | 不把运行中请求简单当作没执行；区分未提交、已确定失败和结果不明 |
| 结果不明 | 显示“结果待确认”，说明不能自动补做 | 优先查询/核对；无法核对时不得自动重发，用户明确再生成才建立新请求 |
| 规划/编辑/保存失败 | 保留输入和原结果，提供明确重试 | 不用演示图片、旧版本或假成功状态掩盖错误 |

建议本地先限制两个图片请求并行，以配置调节服务吞吐；这只是技术并发，不是用户额度。进度显示完成张数与当前阶段，不伪造精确剩余时间。

检查、自动修复、超时与重新连接等状态由同一个任务视图承接，不另建运维流程。无效状态不允许在前端“修正显示”而掩盖后台重复调用。

## 7. 素材、收藏、复用与删除

### 7.1 两类保存，两个用途

创作记录自动保留过程；素材库只展示用户主动加入或直接上传的可复用内容。不得把所有生成结果都自动入库。

生成结果及历史详情均有“加入素材库”。可保存单图或整套当前选用版本；默认自动命名，可改名和选分类，不要求填额外表单。整套作为一个作品条目，保留页序、成图、AI 底图、已有人工图层、必要源素材和生成设置。

收藏为独立快照，不跟随原任务更新。继续编辑时以收藏快照创建创作副本，完成后不静默覆盖原收藏；要保存新版，用户再次明确加入素材库。重复收藏同一版本提示已收藏，允许打开已有条目，避免无意重复。

换商品复用只带风格和页面结构，不带旧商品参数、原商品图或专属文案；必须补新商品依据。生成作品默认作为风格参考，其中旧文字和旧商品不能被当作新商品事实。同商品继续创作保留原始商品资料。上述动作都只准备输入，点击生成后才调用模型。

风格预设与作品收藏是两个功能。工作台的风格区域提供“保存为风格”，保存配色、字体/图标风格、文案语气、可复用的风格描述及参考；通过风格选择器应用、改名或删除。不包含旧商品事实和专属文案，不锁定尺寸，应用时不覆盖当前商品图片或自动生成。品牌色与常用字体偏好也可独立保存，保持轻量，不建立企业品牌管理后台。

收藏快照保留当时的商品事实与适用的 AI 底图报告，报告仍只对应原 AI 底图；这是复制既有证据，不是收藏时重新审查。历史源记录删除后，收藏的必要编辑数据、素材及证据仍可使用。

### 7.2 删除方式：参考创客贴，保护已有作品

已实际进入创客贴主站“我的空间”及回收站；页面快照分别列出“移入回收站”“恢复”“彻底删除”，回收站页面明确提示资源超过 30 天自动删除。当前回收站为空，未选择或删除任何条目，不能声称已验证按钮启用、恢复结果、连带影响或后台清理实现。AI 电商“任务/结果图”是另一组页面，不能混同。[工作区截图](research/assets/chuangkit-2026-09-03/38-main-my-library.png)、[回收站截图](research/assets/chuangkit-2026-09-03/40-recycle-bin-rule.png)、[本轮记录](research/2026-09-03-创客贴调研记录.md#第六轮访谈补充删除方式核对)。官方团队说明也列有 [30 天回收站](https://www.chuangkit.com/price/company)。

建议采用“删除 → 回收站 → 恢复/彻底删除”的交互，不复制会员或团队限制：

- 卡片“更多”中提供删除，确认弹窗说明删除对象，以及“不影响已收藏副本或其他作品”。
- 历史与素材库分别从各自入口访问回收站，可按来源筛选，避免多一个常驻主导航。
- 回收站保留 30 天，显示剩余天数，允许恢复或提前彻底删除；移入前明确提示到期自动清理。本地服务关闭时不会执行清理，重新启动后按到期时间处理，不能把停机误当作重新获得 30 天。
- 彻底删除再次确认，不提供“一键清空所有记录”。被其他作品/快照使用的图片不随原入口删除而丢失；真正无引用的文件才可回收。
- 正在生成的任务先停止后续任务，再允许移入回收站；在途调用归档完成前不得彻底删除其记录。
- 从套图中移除一页只是编辑当前组合，不等于删除该页历史或素材收藏。

入口、恢复/彻底删除及 30 天规则参考已观察到的创客贴页面；引用保护、运行中任务保护及本地清理调度是我们自己的实现要求，须随本稿确认，不声称已验证竞品采用同样实现。

## 8. 下载与交付图片

| 形式 | 行为 |
|---|---|
| 单张 PNG/JPG | 任一已有版本均可下载；默认原尺寸、PNG；JPG 不支持透明，转换时明确使用白底 |
| 多张/整组 ZIP | 默认采用每页当前选用版本，也可明确选择图片；文件名按页序/用途组织 |
| 拼成长图 | 按当前页序或用户选择顺序，等比统一宽度；不拉伸。默认宽度 2048，可选较小宽度；超出导出安全限制时提示改 ZIP，不静默裁掉页面 |
| 部分成功 | 可以下载已有图片；导出前显示缺失页/候选，不把它们伪装成空白成图 |

评分低、检查中或检查未完成不阻止下载。没有图片文件、文件损坏或导出失败可以阻止该次下载，但必须解释为技术错误，不能叫审核不通过。

ZIP 默认只有图片，不自动塞 QA JSON、模型日志或源素材。PSD/通用编辑工程不提供；本地仍保存可继续编辑的数据和关联版本。

## 9. 实施边界与本地运行

### 9.1 共用实现，不做五套系统

| 内部模块 | 负责的内容 |
|---|---|
| 创作与页面配置 | 五工具差异、输入草稿、页面/模块、事实及提交快照 |
| 任务执行 | 生成、AI 修改、检查、一次修复；稳定请求标识、局部持久化与恢复 |
| 图片与编辑版本 | AI 底图、人工图层、合成图、候选/父版本及当前选图 |
| 素材与作品 | 原始文件、用途、收藏快照、引用保护及回收站 |
| 质量检查 | 统一评分口径、证据、未完成状态及组合报告，不承担审批 |
| 导出与模型适配 | 图片/ZIP/长图；部署能力、模型请求及返回尺寸核验 |

保留目前 React/TypeScript、FastAPI/Python、SQLite 和本地文件的技术基础作为默认方案，模块和页面可以重写；不因重构额外引入 Redis、复杂微服务或通用 Agent 平台。

尺寸、参考图上限、模型/部署、评分阈值、并发和字体目录由固定服务端配置管理；业务界面只显示必要创作参数。密钥及令牌不得放前端、日志、作品包或截图中。

### 9.2 新旧运行隔离

- 新版本使用独立运行根目录，例如项目下 data-refactor；数据库、素材、生成结果、导出、缓存、日志、PID 都随该目录隔离，并纳入 Git 忽略。
- 不把 Git 分支当作数据隔离。旧脚本日志和 PID 固定在仓库目录，需要重构时一起调整。
- 首次启动为空白创作记录；自有案例独立作为示例资源，不注入伪装成新生成结果的历史记录。
- 本地默认只绑定回环地址；不新增账号体系，也不宣称已具备多用户安全。
- 先保留旧 data 和 image_qa_mvp/generated；新版本可独立运行后，如需要清理，再核对路径并备份。任务目录、原始资料、PPT、研究截图、examples 和周报不清理。
- 新 Studio 默认不读取旧 `.env`，不隐式启用 Azure。当前本地生成、A+ 规划和质检通过可领取的 Codex 任务包与完成接口衔接；没有执行者时明确显示等待，不回填伪结果。预置 Codex 成图仅用于无现场调用的演示回放。

### 9.3 实现顺序

1. 建新数据与状态模型，移除旧项目/模板/审批门禁依赖，建立固定能力配置。
2. 跑通代表性单图的上传、生成、逐候选保存、评分、一次修复、查看与下载。
3. 补齐套图、A+ 及五工具差异，完成局部重试、停止和恢复。
4. 完成统一编辑器、版本、素材收藏、复用及回收站。
5. 完成各类导出、异常回归、UI 验收与真实模型效果验收。

不把只接了按钮或只跑通本地演示当作功能完成。不在未获后续指令时自动提交、推送或部署到外部环境。

### 10.2 Codex 模型与执行边界验收
