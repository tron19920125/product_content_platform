# Prompt Optimizer 与 Prompt Garden 融入统一 IP 调研

> 调研时间：2026-08-04
> 范围：仅使用项目官方仓库、官方文档、Prompt Garden 网站自身。统一 IP 指“AI 商品图文内容生产与智能质检平台”，不包含 3D/白模链路。

## 一、结论

这两个产品最值得借鉴的不是“再加一个通用提示词编辑器”，而是把统一 IP 补成一条可治理、可复现、可评测的生产链：

**业务资料 → 变量化 Prompt → 优化/版本 → 固定输入对比出图 → QA 评测 → 合格 Prompt 与样例沉淀为资产 → 批量复用。**

建议新增一个“Prompt 资产与实验中心”，但只面向管理员、算法工程师和高级运营；普通业务用户仍走产品资料、模板选择、生成、审核的简化流程。

## 二、两个参考产品的定位与关键能力

### 1. Prompt Optimizer

Prompt Optimizer 定位为通用 AI 提示词优化、测试、评估和资产沉淀工具，支持 Web、桌面、Chrome 扩展和 Docker。官方说明列出的核心能力包括：

- System Prompt 与 User Prompt 两种优化模式，多轮迭代优化；
- “分析提示词”和“执行后评估”分离，支持单结果评估、多结果对比评估，并把评估建议应用回工作区；
- OpenAI、Gemini、DeepSeek、Grok、智谱、SiliconFlow、MiniMax 等多模型；
- 文生图、图生图、多图生图、参考图风格学习及模型参数配置；
- 变量、批量替换、变量预览和智能填充；
- Prompt 模板、自定义模板、版本历史、收藏、标签、媒体和来源绑定；
- Prompt Garden 导入、JSON/资源包/HTML/PNG 导入导出；
- MCP 对外集成。

来源：[官方仓库 README](https://github.com/linshenkx/prompt-optimizer)、[官方测试与评估文档](https://docs.always200.com/user/testing-evaluation/)、[官方模型测试策略](https://docs.always200.com/user/model-testing-strategy/)、[官方模板管理文档](https://docs.always200.com/basic/templates/)。

其中最重要的方法论是：优化模型只负责分析和改 Prompt，真实目标模型的执行结果才是评测证据；对比 Prompt 版本时固定模型与输入，对比模型时固定 Prompt 与输入。这非常适合统一 IP 的商品图生成效果评测。

### 2. Prompt Garden

Prompt Garden 定位为精选 Prompt、案例和媒体素材的发现入口。调研时首页展示 84 个图像 Prompt、8 个分类，并支持图像/文本、文生图/图生图、搜索、筛选、标签和案例图浏览。内容类型包括流程图、海报、信息图、网站 Mockup、知识卡片等。

它与 Prompt Optimizer 通过导入码衔接：基础码如 `NB-001`，也可使用 `NB-001@ex-2` 指定示例。导入后可恢复 Prompt、变量默认值或示例参数、媒体，并按 Prompt 类型路由到对应工作区；保存为收藏时还保留来源链接与导入码。

来源：[Prompt Garden 官方网站](https://garden.always200.com/)、[官方 Prompt Garden 集成文档](https://docs.always200.com/basic/prompt-garden/)、[官方收藏与导入文档](https://docs.always200.com/basic/favorites/)。

## 三、可复用的数据模型

建议借鉴概念但按本项目重新设计，不直接复制代码。

| 数据对象 | 建议字段 | 在统一 IP 中的用途 |
|---|---|---|
| `PromptAsset` | id、名称、场景、类型、正文、变量 Schema、标签、状态、来源、适用模型 | 可复用 Prompt 主资产 |
| `PromptVersion` | asset_id、版本号、正文、修改说明、创建时间、父版本、发布状态 | 追溯 Prompt 演进，支持回滚 |
| `PromptVariable` | key、业务名称、类型、必填、默认值、枚举、校验规则、敏感级别 | 将商品、品牌、场景、版式要求结构化 |
| `PromptExample` | 变量快照、输入图、模型、模型参数、种子、输出图、QA 结果 | 提供可复现的黄金样例 |
| `PromptSource` | source_type、source_id/import_code、source_url、导入时间、授权状态 | 记录内部来源或外部参考来源 |
| `ModelProfile` | provider、model_id、能力、参数 Schema、成本、时延、可用区域 | 多模型适配与路由 |
| `Experiment` | Prompt 版本、模型、固定输入集、候选数、执行时间 | 一次可复现的 A/B 或多模型实验 |
| `EvaluationResult` | 评测规则、分项分数、通过状态、问题证据、人工结论 | 接入现有智能质检能力 |
| `PublishedRecipe` | PromptVersion、ModelProfile、默认参数、模板、QA Policy、黄金样例 | 真正投产的“生成配方” |

Prompt Optimizer 对“历史”和“收藏”的区分也值得保留：历史用于工作过程和版本链；收藏用于已经验证、可跨场景复用的精选成果。官方收藏模型还会携带标题、说明、分类、标签、工作区模式、图片、封面、变量、示例、版本和来源信息。[来源](https://docs.always200.com/basic/favorites/)

## 四、建议融入统一 IP 的能力

| 建议模块 | 借鉴能力 | 与现有 IP 的结合方式 | 优先级 |
|---|---|---|---|
| Prompt 变量化与智能填充 | 变量工作区、核心变量推导其他变量 | 将 `ProductProfile`、`BrandProfile`、`PagePlan` 映射为 Prompt 变量；缺失字段由 Agent 建议但需用户确认 | P0 |
| Prompt 版本管理 | 原始/工作区/v1-vN、历史链、回滚 | 每次发布生成配方固定 Prompt 版本，结果可追溯 | P0 |
| 真实出图对比评测 | 单结果评估、多结果对比评估 | 复用现有 OCR、视觉漂移、LLM Review，把“哪个 Prompt 更好”建立在真实出图上 | P0 |
| Prompt 配方库 | 收藏、标签、分类、媒体、可复现实例 | 将通过 QA 的 Prompt + 模型 + 参数 + 输入样例 + 模板保存为 `PublishedRecipe` | P0 |
| 多模型适配层 | 文本模型/图像模型分离，Provider 适配器 | 优化 Agent 和真实生图模型分离；允许按品类、成本、质量路由 | P0/P1 |
| 图像 Prompt 工作台 | 文生图、图生图、多图生图 | 作为专家模式，普通业务界面只暴露业务字段 | P1 |
| 参考图反推变量 | 复刻功能从图像提取主体、构图、色彩、光影、风格 | 用户上传竞品/品牌参考图后，形成可编辑的视觉变量和版式建议 | P1 |
| 风格学习 | 保留商品主体、提取风格/构图/色彩 | 生成品牌风格草案，但必须经过品牌规则和版权审核 | P1 |
| 内部 Prompt Garden | 搜索、分类、标签、案例卡、导入码 | 建企业内“商品图配方花园”：按品类、品牌档位、页面类型、渠道筛选，一键套用并生成副本 | P1 |
| Prompt 自动优化闭环 | 分析→优化→测试→评估→应用建议→新版本 | QA 失败时把可归因问题转换为 Prompt 修订建议；验证后才发布，不直接自动覆盖生产版本 | P1 |
| 来源绑定与资源包 | 导入码、来源链接、媒体一起备份 | Prompt/图片/模板/模型参数/QA 报告一起导出，支持审计和迁移 | P1 |
| MCP/API 能力 | MCP 对外暴露优化工具 | 后期可供其他 Agent 调用 Prompt 优化、查询配方、运行评测 | P2 |

## 五、推荐工作流

1. 业务资料进入 `ProductProfile`，页面目标进入 `PagePlan`。
2. 系统选择一个已发布 `PublishedRecipe`，将资料填入变量。
3. 优化 Agent 只对缺失、冲突或低质量部分提出 Prompt 修改，不直接改生产版本。
4. 在固定产品资料、参考图和模板条件下，执行 `原版 / 工作区 / 候选版本` 出图。
5. 现有智能质检执行 OCR、主体遮挡、版式、商品一致性、品牌规则和 LLM 综合审查。
6. 对比评估选出更优版本；人工确认后发布为新版本。
7. 通过 QA 的版本连同模型参数、输入样例、输出样例和评测证据进入内部“配方花园”。
8. 业务用户以后从配方花园选用，不需要接触原始 Prompt。

该设计直接借鉴官方建议的实验原则：比较 Prompt 版本时固定模型和输入；比较模型时固定 Prompt 和输入；多图模式还要固定图片集合、顺序和引用关系。[来源](https://docs.always200.com/user/model-testing-strategy/)

## 六、不建议直接融入的内容

- **完整通用 Prompt Optimizer UI**：业务人员不需要理解 System/User Prompt、多消息和复杂工具调用；只保留专家工作台。
- **公开社区 Prompt 市场**：客户 Prompt、商品和参考图通常敏感，应先建设企业内部库；外部 Garden 只作为设计参考或经过审核的导入来源。
- **浏览器直接保存企业 API Key**：官方纯前端方案强调数据本地处理，但 README 也明确提醒公开前端部署中 `VITE_*` 值会暴露在浏览器资源中。企业系统应通过后端模型网关、Key Vault 和权限审计调用。[来源](https://github.com/linshenkx/prompt-optimizer)
- **HTML/PNG 内嵌可导入数据作为主交换格式**：便于分享但存在敏感信息泄漏、压缩后失效和数据治理困难；企业内优先使用受控 JSON/ZIP 包和对象存储引用。
- **把所有 QA 问题都归因给 Prompt**：文字排版、模板安全区、字体和图层问题应由确定性合成引擎修复，不应通过不断扩写 Prompt 解决。
- **直接照搬外部艺术风格 Prompt**：商品营销存在品牌、版权、肖像、商标和风格模仿风险，应只抽取通用的构图、色彩、光线和版式变量。

## 七、许可、版权与安全风险

### 1. 软件许可

Prompt Optimizer 官方仓库明确采用 **GNU AGPL v3.0 only**。其许可证说明，网络服务器运行修改版本并向用户提供服务时，需要向这些用户提供对应源代码。因此：

- 不建议把其代码直接复制、修改后合入计划闭源交付的统一 IP；
- 可以借鉴公开功能、交互方法、数据概念并进行独立实现；
- 若计划复用代码、前端组件或部署原项目，应先做法务评估，明确是否独立服务、是否构成衍生作品以及源码提供义务；
- 文档中的功能描述不能替代正式法律意见。

来源：[官方 LICENSE](https://github.com/linshenkx/prompt-optimizer/blob/develop/LICENSE)。

### 2. Prompt 与媒体内容

Prompt Garden 首页仅标示版权声明，不能由此推定每条 Prompt、示例图或媒体都可用于客户商业项目。建议内部导入流程强制记录来源、作者/提交者、授权状态、适用范围和审批人；授权未确认的外部内容只能用于研究，不进入生产配方库。

### 3. 数据与模型风险

- 外部 Prompt 可能包含恶意指令、品牌冲突或不可见的敏感变量，需要导入扫描和人工审核；
- 参考图反推 Prompt 不能证明拥有参考图或风格的使用权；
- 多模型评测需记录模型版本和参数，否则结果不可复现；
- 生产 Prompt 发布应采用审批和回滚机制，QA 建议不能自动覆盖线上版本。

## 八、4—8 周解决方案阶段建议

| 阶段 | 范围 | 结果 |
|---|---|---|
| 第 1—2 周 | PromptAsset、PromptVersion、变量 Schema、模型适配接口 | 能保存、版本化和执行变量 Prompt |
| 第 2—4 周 | 固定输入的多版本出图、接入现有 QA、对比报告 | 能用真实图片证据比较 Prompt 版本 |
| 第 4—6 周 | PublishedRecipe、内部配方库、标签搜索、黄金样例 | 验证通过的配方可被业务复用 |
| 第 6—8 周（可选） | 参考图变量提取、多模型对比、发布审批和回滚 | 形成专家优化闭环和生产治理 |

首期不做公开社区、通用多消息工作区、浏览器直连全部模型、MCP 和复杂分享格式。

## 九、统一 IP 的能力表述建议

融入上述能力后，统一 IP 可以从“生成 + 质检平台”升级为：

> **面向商品内容生产的 Prompt 配方、生成、图文合成、智能质检与持续优化平台。**

对外强调的核心差异不是“能编辑 Prompt”，而是：**每个生产 Prompt 都有业务变量、版本、模型参数、真实样例、QA 证据、发布状态和可追溯来源。**
