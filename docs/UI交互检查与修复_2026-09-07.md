# Studio UI 交互检查与修复

日期：2026-09-07。项目：Product Content Studio。分支：`codex/product-studio-refactor`。

本轮基于“tech ip 优化”任务记录、重构实施规格和实际代码，检查新版 Studio 的五个创作工具、素材库、创作记录、详情弹窗、手动编辑器及导出。原有未提交修改继续保留。

## 修复内容

| 范围 | 问题与修复后的行为 |
| --- | --- |
| 工具切换 | 快速点击“场景图 → 电商套图”时，旧请求会把页面带回场景图。现在最后一次导航生效，切到素材库也会取消旧导航结果。 |
| 草稿恢复 | 刷新总回到电商套图，示例草稿丢失回放状态。现在记住工具和所选草稿，并在输入仍匹配时恢复示例回放。 |
| 新建创作 | 补充显式新建入口，先保存现有输入，再创建独立空白草稿。 |
| 保存失败 | 保留输入、显示错误和“重试保存”；未保存时关闭或刷新会触发浏览器离开确认。 |
| 重复生成 | 防止连续触发；请求已接收但响应丢失时保留提交标识及原始版本号，重试取回同一次任务。 |
| 图片上传 | 操作期间避免切换导致图片串入其他草稿；数量使用能力配置，校验总参考数、Logo 替换和文件大小；已成功上传的前序图片继续保留。 |
| 素材选入 | 商品图、风格参考和 Logo 选入后回到当前创作；Logo 更新会加载对应资源。 |
| 参考限制 | 示例选择和风格预设应用提前检查数量；AI 修改明确预留底图位置。 |
| 页面与选图 | 保留最后一页，零个待生成页面时禁止提交；已移除或跳过页面不继续进入当前选图、收藏和导出；当前选用版本有可见标记。 |
| A+ 方案 | 恢复方案前保存输入，避免旧版本冲突和迟到的自动保存覆盖恢复结果；切换草稿时清理旧方案列表。规划失败保留原输入。 |
| 弹窗与键盘 | 打开时聚焦可见控件，Tab 在弹窗内循环，Esc 关闭最上层弹窗，关闭后返回触发控件。隐藏上传控件不会被当作初始焦点。 |
| 操作反馈 | 异步操作显示处理中状态；错误浮层显示在详情、素材选择等弹窗之上。 |
| 删除当前创作 | 删除后清空当前引用，继续创作时加载有效草稿；后端同时拒绝向回收站记录保存或创建新生成任务。 |
| 回收站 | 素材选择器只读取有效素材；回收站卡片不再直接应用风格或选入已删除素材；记录抽屉不继承回收站的禁用状态。 |
| 搜索与改名 | 名称搜索忽略首尾空格和大小写，展示无匹配结果；空白名称不能保存，支持回车提交，计数随筛选更新。 |
| 编辑器撤销 | 原实现把可变引用放在延迟执行的状态更新中，部分情况下记录了修改后的内容。现在先截取修改前快照，删除、恢复和重做保持正确。 |
| 丢弃编辑草稿 | 取消待执行自动保存，等待在途保存结束，再丢弃；同时清空撤销、重做、选中对象和编辑状态，防止旧草稿复活。 |
| 完成编辑 | 完成、返回、上传期间阻止冲突操作；保存、渲染和应用使用同一份图层快照。失败时留在编辑器并保留输入。 |
| 图层操作 | 输入框删除键优先编辑文字，Esc 退出文字编辑；锁定层限制修改；旋转后缩放沿对象自身坐标计算，图片保持比例；单击不再制造空撤销记录，指针取消会结束拖动。 |
| 导出与收藏 | 勾选图片时导出对应集合，否则按页面顺序导出当前选图；作品快照保留 Logo 引用；缺页统计不包含跳过页面。 |
| 窄屏和短窗口 | 低于 1280 像素时设置折叠为抽屉，提供关闭、遮罩和 Esc；图标导航保留名称；详情侧栏、按钮和顶部关闭控件保持可操作。 |

## 验证方法

使用独立临时数据运行真实 FastAPI 服务及 Chromium。示例生成使用项目内的回放接口；只在验证断网、延迟、规划失败等情况时对相关浏览器请求注入故障。没有使用现有工作区创作记录作为测试数据。

- 浏览器回归：`frontend/tests/studio-ui.mjs`，29 个场景全部通过。
- 后端回归：共 150 项，149 项通过，1 项 Windows 字体发现测试在 macOS 按条件跳过。
- TypeScript 检查、Vite 生产构建和 `git diff --check`。
- 校验实际下载的 PNG/JPG 文件头、ZIP 内文件及顺序、长图像素宽度；截图检查 1000、1280、1440 像素宽度和编辑器。

最终机器可读浏览器结果和截图放在 [`ui-audit-2026-09-07`](ui-audit-2026-09-07/) 中。

## 复跑浏览器回归

必须使用专门的临时数据目录；脚本会创建、重命名、回收和删除验收素材。

```bash
# 在项目根目录，终端一：先完成 frontend 构建
PCP_STUDIO_DATA_ROOT="$(mktemp -d)/studio" PCP_STUDIO_PORT=8021 bash scripts/start_studio.sh

# 终端二：Node 和 Playwright 可使用本机现有安装
STUDIO_TEST_URL=http://127.0.0.1:8021 \
PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs \
CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
node frontend/tests/studio-ui.mjs
```

若 Playwright 已可被项目解析，可省略 `PLAYWRIGHT_MODULE`；若使用 Playwright 自带浏览器，可省略 `CHROME_PATH`。`STUDIO_TEST_FILTER` 接受测试名称正则，`STUDIO_TEST_OUTPUT` 可指定截图与 JSON 输出目录。

## 验收边界

这轮验证覆盖本地 UI、保存、任务提交与状态展示、回放、编辑及导出。项目目前仍没有常驻的自动图片执行器，真实生成、实时 A+ 规划服务和模型质检效果需要在执行端可用时另行验收。没有将示例回放描述为实时生成，也没有把已通过的回归数量视为“所有潜在问题均已消除”。
