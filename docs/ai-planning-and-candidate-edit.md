# AI 内容规划与候选图定向修改

本文说明两条新增的可审计工作流：AI 规划建议，以及只修改某一张候选图。两者都采用“先生成建议或新版本，再由用户确认”的方式，不会静默覆盖已确认内容。

## 1. AI 内容规划

### 用户流程

1. 创建项目，填写商品名称、SKU、品类、卖点、已确认参数等商品事实。
2. 上传商品外观或局部细节图，选择项目使用的版式库。
3. 点击“AI 生成内容规划”或“重新规划文案”。页面会持续显示排队、LLM 规划或失败状态。
4. 规划完成后，对比当前版本与建议版本。可以按页全选，也可以只选择标题、正文或视觉目标中的某些字段。
5. 点击“应用所选”，系统强制创建新的规划草稿版本。之后仍可直接人工修改、保存草稿或确认规划。
6. 不想采用时点击“暂不采用”。该次运行会保留在审计记录中，但刷新页面后不再反复弹出。

### 输入与约束

规划器接收的是：

- 商品档案中的已确认文本事实；
- 当前版式库中已发布模板的页面类型、场景提示和构图约束；
- 可用的商品/细节参考图，最多发送前三张给多模态 LLM；
- 重新规划时的当前规划版本，用于产生可比较的新建议。

LLM 必须返回结构化的每页 `title`、`body`、`visual_goal`、事实引用和规划理由。后端会再次校验页面集合及数字事实。建议中出现档案以外的数字时，该建议不会直接使用，而会降级到确定性、事实安全的文案。LLM 连接失败也不会卡死流程：系统会返回明确的降级标识与错误原因，用户仍可演示、修改或重新发起规划。

### 版本与审计

每次运行保存以下信息：运行状态、所用版式库、基准规划版本、商品事实快照、模板约束快照、素材 ID/文件名/用途、建议结果、错误或降级原因、最终采用的页和字段、新规划版本号及时间。API 不返回素材的后端存储路径。

相关接口：

- `POST /api/projects/{project_id}/planning-runs`
- `GET /api/projects/{project_id}/planning-runs`
- `GET /api/projects/{project_id}/planning-runs/{run_id}`
- `POST /api/projects/{project_id}/planning-runs/{run_id}/apply`
- `POST /api/projects/{project_id}/planning-runs/{run_id}/dismiss`

## 2. 候选图定向修改

### 用户流程

1. 在已生成的候选图上点击“继续修改此图”。
2. 输入自然语言视觉要求，例如“保持商品角度不变，把环境改成清晨柔和侧光，并增加地面反射”。
3. 为这一次修改选择 Low、Medium 或 High；点击“仅重新生成此图”。
4. 页面只为该候选显示“理解要求 → 编辑图片 → 重新排版 → 质检”的进度；其他页面不会重跑。
5. 修改成功后，原候选保留，新候选带有来源候选、用户要求和质检计划，可在版本记录中追溯。只有目标页的旧审核决定会失效，需要重新确认。

纯文字内容、字号、颜色、位置等需求应使用“调整文字排版”。后端也会拒绝明显的纯排版请求，避免为不需要生图的修改消耗模型调用。

任意文字框、字体预览、AI 初排、版本化保存和“手动质检/跳过质检”的完整规则见 [可编辑文字图层工作流](text-layout-workflow.md)。

### 实际图片链路

模型编辑的主输入是当前候选的无营销文字 `base.png`，而不是带有后期文字层的最终图。同时附带项目原始商品/细节参考图，帮助保持身份、材质和结构一致性。编辑 Prompt 由以下内容绑定而成：

1. 原候选的生成意图；
2. 用户新增的自然语言要求；
3. 当前页面视觉目标；
4. 模板构图和留白约束；
5. 保持未点名元素、禁止底图营销文字、不要虚构型号参数等防护要求。

图片模型输出新的无字底图后，系统用当前规划中的确定性标题和正文重新生成透明文字层，合成为最终图，并只对目标页面重新执行 OCR、参考一致性、布局、文字与 LLM 审查。修改任务失败时不删除原候选，也不撤销原有审核结果；成功后才要求目标页重新确认。

相关接口：

- `POST /api/candidates/{candidate_id}/edit`
- `GET /api/projects/{project_id}/production`（页面对象含 `history`）

## 3. 环境配置

```dotenv
PCP_PLANNING_MODE=local
PCP_LLM_PLANNING_TIMEOUT=120
PCP_LLM_PLANNING_MAX_ATTEMPTS=3
```

- `PCP_PLANNING_MODE=local`：确定性规划，适合离线演示和自动化测试。
- `PCP_PLANNING_MODE=azure`：使用与多模态质检相同的 Azure OpenAI 审查端点和认证配置。
- 如果不显式设置，规划模式跟随 `PCP_QA_MODE`。
- 候选图修改跟随 `PCP_GENERATION_MODE`；Azure 模式需要有效的图片编辑端点、部署和认证。

Azure 的完整端点及身份配置见 [Azure 部署配置教程](Azure部署配置教程.md)。

## 4. 验收建议

离线功能回归可以把三个模式都设成 `local`，完整验证规划、字段级采用、谱系、重新排版、QA 和导出。真实 Azure 验收时，先访问 `/api/preflight` 确认身份与三个资源路由均可用，然后只对一页、一个候选执行 High 质量修改；通过后再做全量生产，避免在环境问题上浪费图片调用。
